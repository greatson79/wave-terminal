# department-setup — 마스터 채팅으로 부서 만들기

**입력 = 사용자가 붙여 넣은 문장 그대로.** 새로 외울 문구를 요구하지 않는다. 「우리 부서는 [ 이름 ]부서이다 …」로 시작하는 글이 오면 이 스킬을 따른다(대괄호 안이 부서 이야기다).
**마스터는 부서를 새로 만들지 않고, 지금 켜진 작업공간 안에 좌석을 더한다.** 새 master도 새 역할도 만들지 않는다 — 부서장은 **제목이 붙은 워커 좌석**이고, 부서 안에서 마스터와 같은 일을 한다(`directives/HEAD_BRIEF.md`).

## 0. 구조 (사용자에게 한 번 쉽게 말해 준다)
- 지금의 마스터 = 「CEO」(제목만 붙인다). 그 아래 **본부장 · CSO 제목 워커 · 워커 · 리뷰어1 · 리뷰어2**, 모두 다섯 좌석이 부서다.
- 부팅(`cys boot`)은 원래 CSO와 워커 두 좌석을 더해 마스터 포함 3좌석이다. 이 스킬이 부서 다섯 좌석을 따로 더한다.
- 다섯 좌석은 앱 화면에 **저절로** 나타난다. 사용자가 창을 따로 만들 필요가 없다.

## 1. 사전 점검 (좌석을 띄우기 전에)
1. `cys list`로 지금 살아 있는 좌석을 본다. 같은 부서 제목이 이미 있으면 **재사용**으로 따로 센다.
2. 살아 있는 `worker` · `worker-N` 좌석 수를 센다. 한도는 8개이고, 이 부서가 워커 역할 좌석 3개(본부장 · CSO 제목 · 워커)를 쓴다. 자리가 모자라면 숫자를 보여 주고 어떻게 할지 묻는다.
3. 에이전트 설치: `cys agent-detect`. claude가 없으면 여기서 멈추고 설치가 필요하다고 말한다.
4. **리뷰어: 이미 떠 있으면 다시 띄우지 않는다.** `cys list`에서 살아 있는 `reviewer-*` 역할 좌석을 본다. 둘 다 살아 있으면 새 부서는 그 **두 좌석을 공유**한다(판정은 파일이라 공유가 된다). 합의문과 마지막 표에 「리뷰어1·2 = 기존 좌석 공유」라고 적고, 그 좌석 번호를 함께 적는다. 이 좌석에는 같은 역할 이름으로 다시 `launch-agent`를 하지 않는다(같은 역할 이름을 다시 띄우면 먼저 있던 부서의 리뷰어가 뒤로 밀린다). 한 좌석만 살아 있으면 그 좌석은 공유하고, 빠진 한 자리는 **지금 살아 있지 않은 역할 이름**일 때만 띄운다(아니면 「리뷰어N = 없음」으로 보고한다).
   하나도 없을 때만 새로 띄운다: `python3 "${CYS_PACK_DIR:-$HOME/.cys/pack}/bin/javis_orchestra.py" boot-reviewers`(스폰 옵션 없이) 출력의 「후보 <역할> ← <에이전트>」 두 줄이 리뷰어1 · 리뷰어2다. agy·codex가 없으면 이 스크립트가 **Claude 대체**(reviewer-claude-1 · 2)를 알려 준다 — 그대로 쓰고 사용자에게 사실대로 말한다(「둘 다 Claude라 같은 실수를 함께 놓칠 수 있어서 관점을 다르게 줍니다」).

## 2. 합의 (grill-me 두 번 · 사용자 문장의 1~3번)
grill-me 스킬로 사용자의 의도 · 말하지 않은 노하우 · 방향 · 목적 · 원하는 결과물 수준을 끝까지 묻는다. 부서의 문화 · 일하는 방법 · 철학을 **결정론적으로 작동**시킬 방법도 함께 정한다. 질문이 끝나면 정리 보고서를 내고, **한 번 더** grill-me로 빠진 것을 묻는다(생략하지 않는다). 아래도 이 대화에서 정한다:
- 부서 이름(짧게, 끝이 「본부」) · 사용자 이름(제목 첫 조각) · 작업 폴더(기본 = 지금 폴더).
- **본부장 모델**: 기본은 Sonnet 5.5. 심층 리서치가 중요하면 Opus 5.5를 권한다(요금제에 따라 쓸 수 없을 수 있다). 사용자가 고른 것을 합의문에 적는다. 마음대로 올리거나 내리지 않는다.
- 리뷰어 두 좌석의 엔진(1단계 4번) · 부서 작동 방식 = 설계 → 배정 → 제작 → 검수 → 판정을 완료 조건까지 이어 가는 **파이프라인**(`HEAD_BRIEF.md` §1 · §4 · §6).

## 3. 합의문 저장 → 승인
합의문을 `<작업 폴더>/부서설계_<부서이름>.md`로 저장한다(이후 부서 구현의 기준 문서). 포함: 목적 · 다섯 좌석의 역할 · 첫 업무 · 모델과 엔진 선택 · 제목 목록 · 완료 조건 · 「SS급」 기준은 본부장이 **심층 리서치**로 만든다는 약속. 파일 경로를 알리고 **사용자의 승인**을 받는다. 승인 전에는 좌석을 띄우지 않는다.

## 4. 이름 붙이기와 좌석 띄우기 (승인 뒤 · 본부장이 먼저)
제목 모양: `<이름>·<부서이름>·<직책>` — 직책은 본부장 · CSO · 워커 · 리뷰어1 · 리뷰어2. 좌석마다 **서로 다른** 제목을 쓴다. 한 좌석을 띄울 때마다 끝날 때까지 기다리고 다음으로 간다(차례로).
1. CEO 표시: `cys rename "CEO"`(지금 마스터 좌석의 이름표만 바뀐다. 역할은 그대로).
2. 본부장: `cys launch-agent --role worker --agent claude --cwd "<작업 폴더>" --title "<이름>·<부서이름>·본부장" [--model <합의한 모델 슬러그>]`
3. CSO 제목 워커: 같은 명령에 `--title "<이름>·<부서이름>·CSO"`
4. 워커: `--title "<이름>·<부서이름>·워커"`
5. 리뷰어1 · 리뷰어2: 1단계 4번에서 **새로 띄우기로 한 자리만** `cys launch-agent --role <역할> --agent <에이전트> --cwd "<작업 폴더>" --title "<이름>·<부서이름>·리뷰어1"` (2는 리뷰어2). 공유하는 좌석은 띄우지도, 이름표를 바꾸지도, 아래 이름표 등록에 넣지도 않는다.
- 좌석을 띄울 때마다 `cys list`로 **실제 역할**(worker-2 …)과 좌석 번호를 적는다.
- 모델이 사용자의 요금제에서 안 되면 launch-agent가 **실패**로 알려 준다. 길은 **하나**다: 거기서 멈추고 사실대로 말한 뒤 「기본(Sonnet 5.5)으로 시작할까요?」라고 **묻는다**. 사용자가 **「예」라고 한 뒤에만** `--model` 없이 같은 본부장 좌석을 다시 띄운다. 「아니오」이거나 답이 없으면 본부장을 띄우지 않고 **못 한 것**으로 보고한다(본부장이 없으니 나머지 좌석도 띄우지 않는다). 묻지 않고 바꾸지 않고, 다른 모델을 대신 쓰지 않는다.
- 본부장이 안 떠 있으면 나머지를 띄우지 않는다.
- **agy·codex 리뷰어가 설치돼 있어도** 로그인·구독이 안 돼 좌석이 응답하지 않거나 로그인 화면에서 멈추면, 멈추지 말고 **같은 슬롯을 Claude 대체**(`reviewer-claude-1` 또는 `reviewer-claude-2`, `--agent claude`)로 다시 띄우고 사용자에게 「<엔진>을 쓸 수 없어 Claude로 대신했습니다」라고 말한다. 로그인은 사용자가 앱 창에서 하는 일이다 — 대신하지 않는다.
- 좌석마다 이름표 등록(묶음 표시용, 로컬 `~/.cys/naming.json`에 **더한다**; 파일이 깨져 있으면 덮어쓰지 말고 알린다). 실제 역할 · 이름 · 「<부서이름>·<직책>」을 바꿔서 실행:
```bash
python3 - "<실제 역할>" "<이름>" "<부서이름>·<직책>" <<'PY'
import json, os, sys, tempfile
role, name, label = sys.argv[1:4]
p = os.path.join(os.path.expanduser("~"), ".cys", "naming.json")
d = {}
if os.path.exists(p):
    try:
        d = json.load(open(p, encoding="utf-8"))
    except ValueError:
        sys.exit("naming.json 이 깨져 있어 덮어쓰지 않았다")
    if not os.path.exists(p + ".bak"):
        open(p + ".bak", "w", encoding="utf-8").write(open(p, encoding="utf-8").read())
roles = d.setdefault("roles", {})
if not isinstance(roles, dict):
    sys.exit("naming.json 의 roles 가 객체가 아니라 덮어쓰지 않았다")
entry = roles.get(role, {})
if not isinstance(entry, dict):
    sys.exit("naming.json 의 %s 항목이 객체가 아니라 덮어쓰지 않았다" % role)
entry = dict(entry)                 # 기존 필드는 그대로 두고
entry["name"], entry["label"] = name, label   # 이 부서가 정하는 두 값만 바꾼다
roles[role] = entry
os.makedirs(os.path.dirname(p), exist_ok=True)
fd, tmp = tempfile.mkstemp(dir=os.path.dirname(p), prefix=".naming.", suffix=".tmp")
with os.fdopen(fd, "w", encoding="utf-8") as f:
    json.dump(d, f, ensure_ascii=False, indent=2)
os.replace(tmp, p)
print("naming.json 등록:", role, name, label)
PY
```
묶음 표시는 앱이 이 이름 파일을 **다시 읽어 와야** 나타난다. 그 새로 읽기는 이번 버전에서 따로 더하는 중이다. 그때까지는 묶음이 보인다고 말하지 않는다 — 좌석이 모두 떴는지만 보고하고, 묶음은 **확인되지 않음**으로 적는다.

## 5. 본부장에게 하달 맡기기 (다섯 좌석이 모두 뜬 뒤)
1. `부서_하달표_<부서이름>.md`를 작업 폴더에 저장한다: 좌석표(역할 · 좌석 번호 · 제목) · 합의문 경로 · 첫 업무(SS급 기준 심층 리서치) · 완료 조건.
2. **본부장에게만** 한 줄을 보낸다: 「너는 본부장이다. `${CYS_PACK_DIR:-$HOME/.cys/pack}/directives/HEAD_BRIEF.md`를 읽어라. 좌석표와 합의문은 <하달표 경로>에 있다. 다섯 좌석이 모두 떠 있다 — 네가 직접 나머지 네 좌석에 지침 하달과 각성 지시를 보내고, 결과를 나에게 보고하라.」 `cys send --to <본부장 좌석 번호> "…"` → `cys send-key --to <좌석 번호> Return` → `cys read-screen`으로 도착을 확인한다(한 줄만 보낸다). 나머지 네 좌석에는 마스터가 하달하지 않는다.
3. 본부장 보고를 받으면 `cys list`로 실제 상태를 대조해 **표**로 사용자에게 보고한다: 역할 · 좌석 번호 · 제목 · 살아 있음(예/아니오) · 못 한 것. **재사용 · 실패 · 새로 시작**을 따로 센다. 리뷰어를 공유했으면 표에 「리뷰어1·2 = 기존 좌석 공유」와 그 좌석 번호를 적는다. 묶음 표시는 확인되지 않았으면 「확인되지 않음」이라고 적는다.
4. 본부장의 첫 응답에 「본부장 지침을 읽었다」는 뜻이 보이는지 확인한다. 안 보이거나 자기 역할을 모르는 듯 답하면(지침이 자동으로 안 들어갔을 수 있다) 위 한 줄의 문서 경로를 다시 읽게 한다.

## 6. 「재각성」 문장이 오면
「부서가 새로 만들어졌다. 이제 cso, 워커, 리뷰어1, 리뷰어2에게 자신의 역할을 재각성하게 하라」는 적힌 그대로 처리한다. `cys list`에서 제목이 …·본부장 · …·CSO · …·워커 · …·리뷰어1 · …·리뷰어2로 끝나는 좌석을 찾는다. 리뷰어1 · 2가 공유 좌석이면 그 좌석들이다. **본부장에게** 「네 좌석 네 개에 하달 한 줄을 다시 보내 재각성시켜라」를 보내고, 본부장 보고를 받아 5단계 3번의 표를 낸다. 부서가 아직 없으면(본부장 좌석이 없으면) 지어내지 말고 「부서가 아직 없습니다 — 부서 셋팅 문장으로 먼저 만들까요?」라고 묻는다.

## 7. 실패는 있는 그대로 (뭉뚱그리지 않는다)
- **master는 둘이 될 수 없다**: 시스템이 두 번째 master를 거부한다(`privileged role 'master' is held by a live surface`). 부서장은 워커 좌석이라 이 거부와 무관하다.
- **워커 한도**: `worker active-limit reached: N/8` — 지금 워커 좌석 수를 보여 주고 정리할 좌석을 고르게 한다.
- **에이전트 없음/모름**: `unknown agent` 또는 설치 안 됨 — 어느 에이전트인지 말한다.
- **신뢰 · 로그인 화면**: 처음 쓰는 폴더나 로그인 때 화면이 선택을 기다린다. 「앱 창에서 'Yes, I trust this folder'를 눌러 주세요 — 누르면 이어서 진행합니다」라고 안내한다. **마스터가 대신 누르지 않는다.**
이 넷 밖의 이유를 지어내지 않는다. 나온 오류 문장을 그대로 보여 주고, 연결을 사용자에게 떠넘기는 말로 바꾸지 않는다.
